- **评审对象**：`frontend/`（Vue3 工作台 / JSSDK iframe 应用），基线同《回归测试报告.md》（commit `cb28078` + 工作区改动）
- **证据来源**：`test-report/2026-10-09-01/screenshots/`（41 张 E2E 实拍，本文引用以 `./screenshots/…` 相对路径）+ `frontend/src/files/ui/*.vue`、`Home.vue`、`preview.ts`、`styles/` 代码走查
- **与回归报告的关系**：F1~F6 已在回归报告④立项，本文不重复展开；相关建议只标注「收编 / 顺带修复 / 协同」，并在文末总表中合并列出
- **约束**：本文只提 UI/UX 层面的改进，不改变 JSSDK 契约与 S3 行为口径；所有方案以当前代码结构可落地为准

## 二、维度①：界面人性化

### A1 键盘导航体系缺失

- **现状**：列表行是 `li` 的 click 单选（`TreePanel.vue`），无任何键盘支持——方向键不能移动选中、Enter 不能打开、F2/Delete 无绑定、Esc 不能取消选中；截图 `./screenshots/ws-01-tree-render-pass.png` 中列表看似可交互，实际键盘用户完全不可达。
- **对标**：Google Drive 全列表支持 ↑↓ 移动、Enter 打开、F2 重命名、Del 删除、Ctrl+A 全选；VS Code Web 文件树用 roving tabindex，方向键在行间漫游。
- **建议方案**：在列表容器上实现 roving tabindex：`ul` 设 `tabindex=0`，方向键在 `entries` 中移动「焦点选中项」，Enter 触发 `select`（目录则进入），F2 走现有 rename 流、Delete 走现有 removeSelected 流，Esc 清选中并关闭预览。快捷键先收敛到这 5 个，写在帮助 tooltip 里，不铺快捷键面板。
- **优先级**：P1 ｜ 预估 2 人日

### A2 多选与框选能力缺失，批量操作无从谈起

- **现状**：`Home.vue` 的 `selected` 是单对象 `ref<S3ObjectSummary | null>`；工具栏删除/重命名只对单文件生效（`./screenshots/tb-02-delete-pass.png`）。无 Ctrl/Shift 多选、无 hover checkbox、无框选。
- **对标**：Google Drive 支持 Ctrl/Cmd+Click 离散多选、Shift+Click 范围多选、行 hover 浮现 checkbox；Dropbox 选中后顶部浮出「已选 n 项」批量操作条。
- **建议方案**：① `selected` 升级为 `Set<key>`；② 行首加 hover 浮现 checkbox（选中态常显），支持 Ctrl/Shift 修饰；③ 选中 >1 时工具栏删除文案变「删除(n)」，重命名禁用；④ 框选可放二期（canvas 式框选成本高），先落修饰键多选。
- **优先级**：P1 ｜ 预估 3 人日（含 Toolbar/TreePanel/Home 三处联动改造）

### A3 无右键菜单，高频操作入口绕远

- **现状**：所有操作都收在顶部工具栏（`./screenshots/warmup-workspace-baseline-pass.png`），对单个文件做「下载/重命名/删除」需要先选中再移动鼠标到工具栏两端；无 `contextmenu` 处理。
- **对标**：Google Drive / Dropbox 的行右键菜单是第一操作入口，聚合「打开方式、下载、重命名、删除、复制名称」。
- **建议方案**：行级 `@contextmenu.prevent` 弹出轻量菜单（ElDropdown 或自绘浮层，定位到光标），首版 5 项：打开、下载、复制名称、重命名、删除；菜单项逐项消费 features 门控（与 F1 修复同口径：`false` 直接不渲染）。菜单实现做成独立组件供后续 tab/预览区复用。
- **优先级**：P1 ｜ 预估 3 人日（含 features 消费，与 F1 修复协同）

### A4 拖拽上传缺失

- **现状**：上传仅走隐藏 `input[type=file]`（`Toolbar.vue` `pickFiles()`）；`styles/_drop-zone.scss` 已有拖拽样式基建但未接线到工作台。
- **对标**：Dropbox / Google Drive 拖拽文件入窗口即全屏遮罩提示「松开上传到 当前目录」，拖到目录行上该行高亮为目标。
- **建议方案**：workspace 根容器监听 dragenter/dragover/drop，复用 `_drop-zone.scss` 样式做全屏落区；drop 后走现有 `queue.enqueue(files, currentPath)`；二期支持拖到具体目录行（dragover 时高亮该行并以其 key 为目标 prefix）。拒收提示复用现有 toast 口径。
- **优先级**：P1 ｜ 预估 2 人日

### A5 上传无进度反馈、无队列面板

- **现状**：上传期间 UI 无任何变化，进度只以 `uploadProgress` 事件发给宿主（`./screenshots/up-01a-after-upload-no-refresh.png` 顶部事件流可见 0→17，iframe 内无感知）；多文件并发时用户不知道传了几个、哪个失败。
- **对标**：Dropbox 右下角上传气泡：单项进度条 + 汇总「已上传 n/m」+ 失败项重试 + 全部取消；Google Drive 右下角进度面板同构。
- **建议方案**：`upload-queue.ts` 已有逐项状态机，补一个 `UploadPanel.vue` 挂在右下角：进行中显示进度条（queue 已有 loaded/total 回调），终态折叠为「n 个文件已上传」摘要条，失败项提供「重试」；同时按 F6 修法在上传终态接 `tree.fetchDir(force)`（见总表 F6 行，本文 A5/B6 与之顺带合并验收）。
- **优先级**：P1 ｜ 预估 3 人日

### A6 预览打开无 loading、失败无占位

- **现状**：`Home.vue` 以 `void preview.open(entry)` 调用，打开期间预览区保持上一次内容或空白；取流失败后仅靠全局 unhandledrejection 弹 toast（回归报告⑤R2），预览区不落任何失败态（`./screenshots/render-07-render-error-toast-pass.png` 中 guide.md 打开失败后预览区纯白）。
- **对标**：Notion / 飞书文档打开内容先落骨架屏，失败态就地给出「重试」；Google Drive 预览失败有明确错误插画与重试按钮。
- **建议方案**：`createPreview.open()` 内部 try/catch：① 进入即渲染骨架占位（复用 FcSkeleton）；② 失败渲染 `.mmf-preview-error`（错误文案 + 重试按钮，重试即重新 open）；③ `Home.vue` 的 `void` 改为 `.catch(() => {})` 由 preview 内部兜底，消除 console 噪音。
- **优先级**：P1 ｜ 预估 1 人日（顺带回归报告⑤R2 收敛）

### A7 空态缺少引导与主操作

- **现状**：右侧预览区初始为整片空白（`./screenshots/ws-01-tree-render-pass.png`），无「从左侧选择文件以预览」引导；空目录只有一行「此目录为空」（`zh-CN.ts files.tree.empty`），无行动点。
- **对标**：Google Drive 空目录提供「上传文件/新建目录」按钮直达；Notion 空态用插画+一句话+主按钮。
- **建议方案**：① 预览区加初始空态组件（图标+「选择左侧文件进行预览」+ 快捷键提示）；② 空目录 FcEmpty 的 action 插槽放「上传文件」「新建目录」两个次级按钮（消费 features 门控）。
- **优先级**：P2 ｜ 预估 1 人日

### A8 删除不可撤销，确认弹窗是唯一防线

- **现状**：删除有 FcToast.confirm 二次确认（`./screenshots/tb-02-delete-pass.png` 流程正确），但确认后立即真删，无反悔窗口。
- **对标**：Google Drive 删除进回收站并弹「已移至回收站—撤销」snackbar；Gmail 同构。确认弹窗只防误触，撤销才防后悔。
- **建议方案**：与 B7 回收站联动：删除改为「移入 .trash/ 前缀」后，底部 snackbar 提供 5 秒「撤销」（反向 CopyObject+Delete）；若回收站未排期，先做降级版——confirm 文案强化风险（当前已含「目录会连同其内容一并删除」，达标），撤销项挂起等回收站。
- **优先级**：P2 ｜ 预估 2 人日（依赖 B7）

### A9 会话时间信息粗糙且到期后自相矛盾

- **现状**：header 显示「会话剩余: 60 min」粗粒度分钟（`Home.vue` sessionInfo 只算分钟向上取整）；到期遮罩出现后 header 仍残留「会话剩余: 1 min」陈旧标签（`./screenshots/sess-01-expired-mask-pass.png` 遮罩下方可见）。
- **对标**：飞书/Google Workspace 的会话倒计时在最后 5 分钟转为 `mm:ss` 并高亮；终态后所有时间元素同步冻结或隐藏。
- **建议方案**：① `remainingMs < 5min` 时显示 `mm:ss` 并转警示色；② `expired` 后隐藏剩余时间标签（SessionBanner 已有 expired 状态，与 header 共享一个状态源即可）；③ 预警文案「T-5min」术语改成用户语言「将于 5 分钟后到期」（现有 `files.session.warn` 文案偏内部口径）。
- **优先级**：P2 ｜ 预估 1 人日

## 三、维度②：功能合理化

### B1 列表无排序能力

- **现状**：列表固定「目录在前 + S3 字典序」（`tree-store.ts` 聚合顺序），名称/大小/类型表头不可点（`./screenshots/ws-03-paginated-listing-pass.png`），找不到大文件只能肉眼扫。
- **对标**：Google Drive 表头点击排序 + 「排序」菜单（名称/修改时间/大小，正反向），排序偏好记忆。
- **建议方案**：一期做客户端排序即可（当前目录已全量聚合在内存）：表头三列可点，循环「升→降→恢复默认」，箭头指示；排序状态放 preference store 记忆。S3 无服务端排序，目录跨页聚合后客户端排序语义完整。
- **优先级**：P1 ｜ 预估 2 人日

### B2 无搜索与类型筛选

- **现状**：只能逐目录浏览，文件多时无检索手段；`./screenshots/ws-01-tree-render-pass.png` 工具栏无任何过滤入口。
- **对标**：Dropbox 列表上方即时过滤框；Drive 全局搜索（本文不做全局，只做当前目录内）。
- **建议方案**：工具栏右侧加即时过滤输入（防抖 200ms，对当前目录 `entries` 按名称子串过滤）+ 类型 chips（文档/表格/图片/视频/其他，按扩展名分组）；过滤态下列表头显示「n/m 项」。明确标注「仅当前目录」，避免用户误以为是全局搜索。
- **优先级**：P2 ｜ 预估 2 人日

### B3 预览区没有文件语境条与操作入口

- **现状**：预览成功后只有裸内容——无文件名、无大小、无下载、无关闭（`./screenshots/render-01-markdown-pass.png`）；图片按原始尺寸渲染无适配与缩放（`./screenshots/render-02-image-pass.png` 中 logo.png 缩成一个点）；视频固定 ~290px 宽（`./screenshots/render-05-video-pass.png`）。
- **对标**：Google Drive 预览顶栏（文件名 + 下载/打印/打开方式）；飞书预览底部悬浮缩放控件；Figma 画布角落缩放器。
- **建议方案**：预览卡加 header 行：文件名（截断+title）+ 大小 + 右侧「下载」「关闭」图标按钮；图片渲染器加「适应窗口/原始尺寸」切换与 25%~400% 缩放（CSS transform 即可，不必引入大库）；媒体类统一 `max-width:100%` 约束。「打开方式」下拉与 F3 修复的 openWithMenu 共用同一入口（协同项）。
- **优先级**：P1 ｜ 预估 2 人日

### B4 无详情侧栏

- **现状**：文件的 key、精确大小、类型、mime 等元信息无处可看，只有列表里截断的行；S3ObjectSummary 数据都在内存，纯展示缺口。
- **对标**：Google Drive 右侧详情面板（缩略图 + 属性 + 活动），可折叠、选中即刷新。
- **建议方案**：右栏做「预览 / 详情」二态或右侧窄栏（240px，可折叠）：属性表含名称、key（可复制）、类型/扩展名、大小（精确字节+人性化双显）、mime；目录显示对象数。一期不做「活动」页签。
- **优先级**：P2 ｜ 预估 2 人日

### B5 左侧是「单目录列表」而非树，跨目录跳转成本高

- **现状**：`TreePanel.vue` 名为树实为当前目录平铺 + 面包屑回跳（`./screenshots/ws-02a-subdir-pass.png`）；从 `docs/img` 回 `docs` 后再去 `paged` 需要两次面包屑点击，无法总览目录结构。
- **对标**：VS Code Web 持久文件树常驻左栏；Google Drive 用「文件夹导航 + 面包屑」但层级浅时体验成立。
- **建议方案**：做成双视图切换（列表 ⇄ 树）：树视图按已加载目录惰性展开（复用 tree-store 的按 prefix 缓存），目录行带展开箭头；列表视图维持现状。默认列表视图（与 Drive 一致），深度嵌套用户自切树视图。
- **优先级**：P2 ｜ 预估 3 人日

### B6 操作后选中态与预览区不一致

- **现状**：重命名成功后选中高亮丢失（`./screenshots/tb-03-rename-pass.png` 中 renamed.txt 无选中态）；删除成功后预览区仍显示已删文件内容（`./screenshots/tb-02-delete-pass.png` 中 README.md 已删、预览区仍渲染其 markdown）。根因：`Home.vue.onChanged` 只清 `selected`，`watch(selected)` 仅在非空时 `open`，置空不清预览；重命名则整行 key 变化导致选中失联。
- **对标**：Dropbox 重命名后保持选中并就地更新行内编辑；删除后预览区回到空态（与 A7 空态共用）。
- **建议方案**：① rename 成功回调里把 `selected` 换成新 key 的 summary（tree-store 已返回/可查新 entry）；② `selected` 置空时同步 `preview.clear()`；③ 与 F6 同批在装配层验收（上传终态刷新树 + 选中一致性）。
- **优先级**：P1 ｜ 预估 1 人日

### B7 回收站（软删除）缺位

- **现状**：删除即 DeleteObjects 真删，无恢复手段（回归报告④ F1 佐证截图即真实删除）；「回收站」在已排期未做清单中。
- **对标**：Google Drive 回收站：删除项保留 30 天，可恢复/彻底删除/清空。
- **建议方案**：以 `.trash/` 前缀承载：删除 = CopyObject 到 `.trash/<原key>+<时间戳>` 再 DeleteObject；侧导航加「回收站」入口（列表同构，操作换「恢复/彻底删除」）；恢复 = 反向 copy 回原 key。确认弹窗文案同步改为「移入回收站」。需评估桶策略允许 trash 前缀（与宿主约定）。
- **优先级**：P2 ｜ 预估 3 人日 ｜ 收编已排期「回收站」

### B8 分享/外链无占位

- **现状**：界面上没有任何「把文件给他人」的入口；「分享」在已排期未做清单中。
- **对标**：Dropbox 行操作与预览顶栏都有分享按钮；Drive 同。
- **建议方案**：一期先落「复制下载链接」占位：右键菜单 + 预览工具栏加「复制链接」，实现走 `client.get` 的签名 URL（或宿主提供的 download 命令），分享协作（权限/有效期管理）保持 disabled 项加「即将支持」tooltip，让排期项在信息架构里有锚位。
- **优先级**：P2 ｜ 预估 1 人日 ｜ 收编已排期「分享」占位

## 四、维度③：布局仿大厂

### C1 预览舞台无尺寸规范（F5 塌陷的体系性收编）

- **现状**：`.ws__preview-host` 无任何尺寸样式，父容器 flex 居中导致 Monaco 实例塌陷 5×5px（`./screenshots/render-04-monaco-txt-pass.png` 空白、探针 `./screenshots/render-04b-monaco-5x5-collapse-probe-FINDING.png`），即回归报告 F5。
- **对标**：VS Code Web 编辑器容器有明确 `flex:1 + min-height:0` 约束链；Figma 画布容器尺寸恒定，内容缩放适配而非容器塌陷。
- **建议方案**：把「预览舞台」抽象为布局契约：`.ws__preview-host { width:100%; height:100%; min-height:320px; }` 且父级 `.ws__preview` 改 `align-items:stretch`；媒体/编辑器类渲染器统一 `width:100%; max-width:100%` 约束（同时解决 B3 中视频固定宽问题）；补 E2E 断言 `.monaco-editor` boundingBox > 200px 防回归。
- **优先级**：P1 ｜ 预估 1 人日 ｜ 收编 F5（回归报告④已立项）

### C2 信息架构停留在「两栏」，缺左导航层

- **现状**：整体是「列表 + 预览」两栏（`./screenshots/warmup-workspace-baseline-pass.png`），没有承载回收站/树视图/未来分享的空间；工具栏、面包屑、列表全部塞在左卡与顶条里。
- **对标**：Google Drive 三层：左导航（我的云端硬盘/共享/回收站）+ 中列表 + 右详情；VS Code Web 活动栏+侧栏+编辑区+状态栏。
- **建议方案**：在左列表外再套一层 200px 窄导航（图标+文字：「文件」「回收站」B7、「已分享」B8 占位），中栏 = 面包屑 + 工具栏 + 列表，右栏 = 预览/详情（C4 可折叠）。一期窄导航只有两个真实项也不空——为排期项提供统一挂载位。
- **优先级**：P2 ｜ 预估 3 人日

### C3 预览区单实例，无 tab 系统

- **现状**：`createPreview` 单实例，切换文件即 dispose 旧实例（`preview.ts` 契约「切换=丢弃」），连续比对两个文件只能来回重开；「多 tab」在已排期未做清单中。
- **对标**：VS Code Web 编辑器 tab：多文件并存、未保存态圆点、中键关闭；飞书文档多开同理。
- **建议方案**：按排期落地时采用「tab 条 + preview 实例池」：每 tab 一个 container 与 PreviewHandle，激活切换 display 而非销毁（保留滚动/编辑态）；tab 上限建议 8，超出 LRU 关闭；关闭未保存 tab 走 beforeDispose 询问（契约已有该钩子）。本文 C1 的舞台尺寸规范是 tab 布局的前置。
- **优先级**：P1 ｜ 预估 5 人日 ｜ 收编已排期「多 tab 系统」

### C4 侧栏不可折叠、不可调宽

- **现状**：左栏 `minmax(300px, 420px)` 固定网格（`Home.vue` 样式），无折叠按钮、无拖拽分隔条；预览宽屏时被压缩。
- **对标**：VS Code Web 侧栏可整体折叠 + 分隔条拖拽调宽且记忆；飞书文档目录可收起为细条。
- **建议方案**：网格改 `grid-template-columns: var(--sidebar-w, 360px) 1fr`，分隔条 4px 热区拖拽（min 280 / max 560），双击恢复默认；折叠按钮收进工具栏，折叠态只留图标列（配合 C2 窄导航）。宽度写 preference store。
- **优先级**：P2 ｜ 预估 2 人日

### C5 响应式只有单断点，中屏与移动端体验断层

- **现状**：仅 `@media (max-width: 720px)` 一档，堆叠后预览区在列表下方需长滚动；1024 宽度下左栏仍占 420px 上限，预览区偏窄。
- **对标**：Google Drive 三档：宽屏三栏、中屏收详情、窄屏列表全屏+预览浮层。
- **建议方案**：定三断点：≥1280 三栏全量；768~1279 预览区与列表互斥切换（选中文件即覆盖列表，顶部返回条）；<768 单列 + 预览全屏浮层。断点常量收进 `styles/variables.scss` 统一引用。
- **优先级**：P2 ｜ 预估 1 人日

### C6 无底部状态条，上下文信息无处安放

- **现状**：当前路径、对象数、选中数、过滤态、会话状态分散在面包屑/header/工具栏，或不展示。
- **对标**：VS Code Web 底部状态栏集中承载上下文（路径/分支/问题数），是低成本高信息密度的布局件。
- **建议方案**：底部 24px 状态条：左侧「当前路径 + n 项（已选 m）」，右侧「会话剩余时间（替代 header 标签，联动 A9）+ locale 切换」。同时消化 header 里的冗余 tag，让 header 回归纯品牌区。
- **优先级**：P2 ｜ 预估 1 人日

## 五、维度④：细节仿大厂

### D1 文件图标无类型区分

- **现状**：所有文件统一 `ri-file-line`、目录 `ri-folder-line`（`TreePanel.vue` 模板），类型列靠文字 MD/CSV/PNG（`./screenshots/ws-01-tree-render-pass.png`），扫视效率低。
- **对标**：Google Drive / Dropbox 按类型分形着色：文档蓝、表格绿、图片紫/红、视频红、音频橙；Dropbox 用大色块徽标。
- **建议方案**：建 `fileIcon(ext)` 映射表（8~10 组：doc/docx、xls/xlsx/csv、pdf、图片、视频、音频、代码、压缩包、其他），各组指定 remixicon 图标 + 语义色 token（走 `_themes.scss` 变量）；fallback 用中性文件图标。纯前端映射，0 接口改动。
- **优先级**：P1 ｜ 预估 2 人日

### D2 目录名居中、文件名左对齐，同列两套对齐

- **现状**：目录行名字是 `button.fc-button`（Element 按钮样式 text-align:center），文件名是 `span`（左对齐）——`./screenshots/ws-01-tree-render-pass.png` 中 broken/docs/paged 明显居中悬在列中，与下方文件列错位，是实拍可见的对齐 bug。
- **对标**：任何文件管理器（含 Drive/Dropbox）名称列恒左对齐、图标列恒右贴图标。
- **建议方案**：一行修复：`.tree-panel__name { text-align:left; justify-content:flex-start; }`（或目录名不用 fc-button，改 span+click 加 cursor:pointer）。顺带核查按钮态 hover 下划线与文件名 hover 一致。
- **优先级**：P1 ｜ 预估 0.5 人日

### D3 目录行显示「0 B」是噪音

- **现状**：目录行大小列恒显示 0 B（`./screenshots/ws-01-tree-render-pass.png`），语义为假（S3 prefix 无大小概念）。
- **对标**：Drive/Dropbox 目录大小列显示「—」或留空，聚合大小只按需计算。
- **建议方案**：`formatSize` 对 `isDir` 返回「—」；类型列保留「文件夹」。
- **优先级**：P2 ｜ 预估 0.5 人日

### D4 面包屑是纯文本链，无层级下拉

- **现状**：面包屑为「test / docs」文字按钮 + `/` 分隔（`./screenshots/ws-02a-subdir-pass.png`），只能沿祖先回跳，不能横向切到同级目录。
- **对标**：Google Drive 面包屑每级带下拉箭头，点开列出同级目录直接横跳；分隔符用 chevron 而非斜杠。
- **建议方案**：分隔符改 chevron 图标；每级按钮旁挂下拉（列出该级兄弟目录，来自父目录 bucket 缓存，未加载则懒拉一次）；当前级也保留下拉（切同级）。超长路径中间折叠为「…」下拉。
- **优先级**：P2 ｜ 预估 2 人日

### D5 加载骨架与过渡不成体系

- **现状**：首载目录有 FcSkeleton，但行 hover/selected 无 transition，预览切换是硬切，到期遮罩无淡入；骨架只在列表一种形态出现。
- **对标**：Notion 骨架与内容结构同构；飞书所有态切换统一 120~160ms ease。
- **建议方案**：`mixins.scss` 定统一 motion token（fast 120ms / base 160ms），应用于行 hover/selected 背景与预览容器 fade；骨架补两种形态（列表行骨架、预览区内容骨架与 A6 共用）；遮罩加 opacity 过渡。克制，不做弹跳/缩放类动效。
- **优先级**：P2 ｜ 预估 1 人日

### D6 焦点管理缺失，键盘可达性不达标

- **现状**：列表行、面包屑当前级、fallback 下载按钮均非可聚焦元素或无 `:focus-visible` 样式；ElMessageBox 关闭后焦点不归还触发按钮；到期遮罩无焦点陷阱。
- **对标**：VS Code Web 全界面键盘可达；Google Material 规范要求 focus ring 可见、对话框关闭焦点归还。
- **建议方案**：① 行/面包屑当前级补 `tabindex` 与 focus 样式（与 A1 roving tabindex 一并做）；② 全局 `:focus-visible` ring token；③ 对话框/遮罩统一走 ElMessageBox 已有焦点陷阱，遮罩关闭后归还焦点到工具栏；④ 破坏性按钮确认态加 `autofocus` 在「取消」上（防 Enter 误删）。
- **优先级**：P1 ｜ 预估 2 人日

### D7 toast 出现在顶部中央且遮挡 header

- **现状**：错误 toast 弹在页面顶部中央并与 header 重叠（`./screenshots/ws-04b-retry-recovered-pass.png` 中半透明「S3 请求失败」横盖在标题栏上），与品牌区/会话标签互相干扰。
- **对标**：Google Material snackbar 底部左侧；Drive/Dropbox 操作反馈一律右下或右上，绝不遮标题区，且可堆叠。
- **建议方案**：全局 toast offset 改右下（或右上），配置 stacking 与 max 3 条；错误类时长 ≥5s 并带手动关闭；与 A5 上传面板错位（面板右下时 toast 右上），避免同角打架。
- **优先级**：P2 ｜ 预估 0.5 人日

### D8 文案与表格排版细节

- **现状**：① boot 错误标题 `word-break: break-all` 把「#config」断成「#con fig」换行（`./screenshots/boot-01-no-fragment-pass.png`、`./screenshots/boot-03-version-unsupported-pass.png`）；② 「会话剩余: 60 min」半角冒号混排（`zh-CN.ts`）；③ xlsx 预览表格无网格线/斑马纹/粘性表头（`./screenshots/office-02a-xlsx-table-pass.png`），Sheet 切换是裸方块按钮；④ docx 损坏只有一行「Word 文档加载失败」无重试/下载（`./screenshots/office-01-docx-invalid-zip-pass.png`）。
- **对标**：飞书/Notion 文案规范：代码 token 不拆行（`word-break:keep-all` + `<code>` 样式）；表格类预览默认斑马纹+粘头；加载失败就地给「重试 / 下载原文件」双出口。
- **建议方案**：① boot 标题改 `overflow-wrap:anywhere` 并把 `#config / #file` 用 `<code>` 包裹；② 文案统一「会话剩余：60 分钟」（全角冒号 + 中文单位，en-US 同步核查）；③ xlsx/csv-table 渲染器套统一表格样式（斑马纹、粘头、1px 网格、hover 行），Sheet 页签改 ElTabs 样式；④ docx/xlsx 加载失败态补「重试 + 下载原文件」（复用 onDownload）。
- **优先级**：P2 ｜ 预估 1.5 人日
