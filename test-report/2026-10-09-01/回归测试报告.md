## ④ 发现与修复意见清单

> 铁律遵守：以下问题**均未改动 `frontend/src/`**，全部以失败用例/探针脚本+截图+console 证据固定。严重度：P0=主流程不可用或权限承诺失效；P1=一期承诺功能不可用；P2=体验/契约偏差。

### F1（P1）features.*=false 时「UI 隐藏+API 拒绝」承诺失效——UI 路径整链绕过门控，删除真实执行

- **现象**：`features.delete=false` 时：① JSSDK 命令层正确拒绝（4301，feat-01 ✅）；② 但工具栏「删除/重命名/新建目录/上传」按钮照常显示且选中后可点（feat-02）；③ 点删除→确认后 **DeleteObjects 真实发出、对象被真删**、行消失、宿主收到 `fileChanged{action:delete}`（feat-03）。《用户手册》§一字段表与 FAQ 明确承诺「false=对应操作整链禁用（UI 隐藏+API 拒绝）」。
- **证据截图**：![feat-02](./screenshots/feat-02-delete-button-still-enabled-FINDING.png) ![feat-03](./screenshots/feat-03-ui-delete-bypasses-gate-FINDING.png)（顶部事件面板可见 delete 已执行 + ready 事件 configSummary 携带 features:["delete"]）
- **根因分析**：`src/files/ui/Toolbar.vue` 完全不消费 features（组件无该 prop/inject）；且 UI 操作直连管理面 store——`removeSelected()→controller.remove()`、`createDir()→controller.mkdir()`、`rename()→controller.rename()`、`onPicked()→queue.enqueue()`，均不经过 `createM1Overrides` 的 `requireFeature` 门（`src/files/commands.ts`）。门控只落在宿主命令通道上，管理面内链路无第二道门。
- **建议修法**：双管齐下——① Toolbar 注入 `resolveFeatures(config.features)` 结果，false 时 `v-if` 隐藏对应按钮（upload/mkdir/rename/delete 分别对应）；② 防御性兜底：`setupStores`/Toolbar 各动作入口再调 `requireFeature`（或在 `tree-store`/`upload-queue` 构造时注入门控闭包），保证「UI 隐藏失效时内部链路仍拒绝」。
- **严重度**：**P1**（权限/合规承诺失效，破坏性操作可被触发；真实数据安全仍由 S3 凭证 policy 兜底，故不评 P0）

### F2（P1）单文件模式（#file）不渲染内容——source 从未被拉取，仅显示占位卡

- **现象**：`#file={source:{url:…md}}` 打开后只显示「README.md + 单文件预览占位：渲染器接入后可预览/编辑 + 只读/可编辑 tag」；mock 侧记录源对象 **GET 次数=0**（2s 观察窗）。手册 §一形态 B 承诺「只读=无 save 段（预览应用渲染，零写链）」。
- **证据截图**：![file-01](./screenshots/file-01-readonly-plaintext-FINDING.png)
- **根因分析**：`Home.vue` 的 file 分支（`resolveFile()`）仍是 M0 占位实现；`UrlSourceProvider`（`src/sdk/url-source.ts`）与 `urlDataSource`（`src/apps/datasource.ts`）均已实现并测试通过，但装配链（createPreview + registry）只在 workspace 分支接线，file 分支未消费。PROGRESS.md 中 M2 条目「file 模式占位（M2 接渲染器）」即此欠账。
- **建议修法**：file 分支组装 `urlDataSource(new UrlSourceProvider(cfg))` + 复用 `createPreview`：`open({key:'-', name: fileName, size:0})` 走 registry 默认应用；可写形态（有 save 段）默认给 code-editor（Ctrl+S→`provider.put`→notify saved）；只读形态按扩展名选预览应用，未匹配走现有 fallback。
- **严重度**：**P1**（一期承诺形态不可用，整个「单文件嵌入」场景只有壳）

### F3（P2）.csv 默认应用被 code-editor 抢占——csv-table 表格预览不可达

- **现象**：点击 data.csv 打开的是 Monaco 文本编辑器（文本态），`csv-table` 表格预览（papaparse、分页表格）作为默认应用不可达；《第一期文件类型支持计划》§一应用清单中 csv-table 为 CSV 的 view 应用，code-editor 的 csv 属「文本态（与渲染类应用并列『打开方式』）」。tsv 同理受影响。
- **证据截图**：![render-03](./screenshots/render-03-csv-default-hijacked-FINDING.png) ![render-03b](./screenshots/render-03b-csv-default-code-editor-FINDING.png)
- **根因分析**：`src/apps/builtins.ts` 的 `BUILTIN_APP_SPECS` 注册序中 `code-editor`（ext 含 csv/md）排在 `markdown-renderer` 之后、`csv-table` 之前；`AppRegistry.resolveDefault`=注册序首个命中。.md 因 markdown-renderer 注册在前不受影响；.csv/.markdown 源码态命中 code-editor。
- **建议修法**（任选其一或组合）：① 调整注册序——渲染类应用（csv-table 等）先于 code-editor 注册；② `resolveDefault` 增加「actions 含 preview 优先于 edit」的排序规则；③ 补「打开方式」菜单（`openWithMenu` feature 手册已有、UI 未实现），把源码态作为次选。
- **严重度**：**P2**（一期功能被静默挤掉，但有可用替代形态）

### F4（P2）会话到期后通道立即销毁——宿主命令无回包（契约承诺 5000 SESSION_EXPIRED）

- **现象**：ttl 到期遮罩出现后，宿主发 `navigate` 得不到任何 reply（harness 12s 超时，`{"ok":false,"code":-1,"timeout":true}`）；真实 SDK 侧将表现为 4004 TIMEOUT。《JSSDK 接口文档》§七错误码表写明「SESSION_EXPIRED 5000=会话已终态后的任何 cmd」。操作本身未被执行（S3 无新请求），「拒绝执行」语义成立，仅错误码通道缺失。
- **证据截图**：![sess-02](./screenshots/sess-02-cmd-no-reply-after-expiry-pass.png)（reply 原文与断言见 log）
- **根因分析**：`src/boot.ts` 的 `onExpire` 回调在宏任务里 `bus.emit('expired')` 后立即 `bus.destroy()`——message 监听被移除、handlers 清空，此后到达的 cmd 信封无人应答。handlers.ts 的终态门（5000）只在 `session.end()` 与 `bus.destroy()` 之间的微任务窗口内可达，TTL 到期路径实际不可观测。
- **建议修法**：① 保契约：destroy 前留一个最小「终态应答器」（如 `bus.on` 通配或延迟 destroy 一个 tick+），对终态后 cmd 统一 `replyError(5000)`；或 ② 修契约：文档改为「到期后命令静默丢弃（宿主按超时处理）」，实现不动。二者取一，消除文档与行为偏差。
- **严重度**：**P2**（对接方按文档做错误处理会永远走不到 5000 分支）

### F5（P1）Monaco 预览容器塌陷为 5×5px——txt/代码/csv 文本态预览不可视

- **现象**：点击 notes.txt 后 DOM 断言全部通过（`.monaco-editor` 存在、`.view-lines` 含全文），但**预览卡片视觉完全空白**。页面探针（`frontend/e2e/monaco-probe.mjs`）实测：`.ws__preview-host`/`.mmf-preview-stage`/`.monaco-editor` 的 getBoundingClientRect 均为 **5×5 px**（中心点 x≈933,y≈243），`.view-lines` 布局盒 129×54 溢出被 monaco overflow 裁剪。受影响范围=code-editor 应用全部命中类型（txt/代码集/csv/md 源码态）。
- **证据截图**：![render-04 空白预览](./screenshots/render-04-monaco-txt-pass.png) ![探针全景](./screenshots/render-04b-monaco-5x5-collapse-probe-FINDING.png) ![探针元素](./screenshots/render-04c-monaco-preview-element-FINDING.png)
- **根因分析**：`Home.vue` 模板 `<div ref="previewEl" class="ws__preview-host" />` 无任何尺寸样式，其父容器 `.ws__preview`（FcSectionCard）为 `display:flex; align-items:center; justify-content:center`，空 div 在 flex 交叉轴上折叠为最小尺寸；`code.ts` 的 `monaco.editor.create(el,…)` 按容器实测尺寸（5×5）建编辑器且 `overflow:hidden`，此后容器不再变化（automaticLayout 无触发），文本内容虽在 DOM 但不可视。其余渲染器（md/csv 表格/img/video/fallback）追加的是普通块级内容，能把宿主 div 撑开，故仅 Monaco 中招。
- **建议修法**：给 `.ws__preview-host` 显式尺寸（`width:100%; min-height:320px; height:100%` 或 `flex:1`），或 `createPreview` 在 mount 前给 stage 设定尺寸；Monaco 侧也可在 create 时传显式 `width/height` 兜底。加一条 E2E 断言防回归：`.monaco-editor` 的 boundingBox 宽高 > 200px。
- **严重度**：**P1**（一期核心能力「代码/文本编辑器」视觉不可用；数据管线完好，故评 P1 不评 P0）

### F6（P2）上传完成后文件树不自动刷新——新文件「消失」直至手动刷新

- **现象**：上传 `uploaded.txt` 成功（PUT + `uploadDone{key}` 事件均达宿主），但树中无新文件（可见行数=0）；点「刷新」后才出现。对比：mkdir/删除/重命名均即时刷新树（tb-01/02/03 ✅），上传独缺。
- **证据截图**：![up-01a 未刷新](./screenshots/up-01a-after-upload-no-refresh.png) ![up-01b 刷新后](./screenshots/up-01b-after-refresh-pass.png)
- **根因分析**：`Toolbar.onPicked → queue.enqueue()` 后，`UploadQueue` 终态只经 hooks `emit('uploadDone')`（bus 出站），无人调用 `tree.fetchDir(parent,{force:true})`；`setupStores` 也未把 queue 终态接回 tree。
- **建议修法**：装配层把上传终态接树刷新——`createUploadHooks` 的 `onDone/onFailed` 里追加 `tree.refreshParents([key])`（或在 Toolbar 层监听终态后 `loadDir(currentPath,{force:true})`）。
- **严重度**：**P2**（功能最终可达，体验不一致，易被误解为「上传丢了」）
